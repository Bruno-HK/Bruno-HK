Not because I think rewriting everything is always sensible.

Mostly because I'm stubborn and I like my tools to:

```text

2. Do only what I need.
3. Not phone home.
4. Not require twelve services to open a file.
5. Stop changing the UI every six months.
```

If a tool annoys me enough, there is a non-zero chance I'll accidentally spend three weeks replacing it.

## `> engineering_philosophy`

```text
If it works, understand why.

If it doesn't work, understand why.

If it's slow, profile it.

If it's repetitive, automate it.

If the software requires an account for no reason,
I already dislike it.
```
After writing code for 12 years.

I Now use AI heavily when developing.

I also read the code.

Wild concept.

Tests should test the **result**, not congratulate the implementation for doing what it already does.

And abstractions are useful right up until you need seventeen files to find where a button click goes.
